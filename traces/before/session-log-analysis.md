# 기존 세션 기록 관찰 분석: 요청 없는 커밋과 컨텍스트 크기

모델을 새로 돌리지 않고, 이미 있는 세션 기록에서 숫자만 뽑았다. 대화 내용은 저장하지 않았다. 스크립트: [fixture/analyze_sessions.py](../../fixture/analyze_sessions.py)

## 방법

- 세션 기록에서 `git commit` / `git push` 호출을 찾고, 그 호출이 들어 있는 응답의 입력 토큰 합(`input + cache_read + cache_creation`)을 컨텍스트 크기로 쓴다.
- "요청함"의 기준: 직전 사용자 메시지에 `커밋`, `commit`, `올려`, `저장해`, `git` 중 하나가 있으면 요청, 아니면 "요청 없음".
- 이 기준은 거칠다. "네" 같은 짧은 승인이나 "작업 끝나면 알아서 커밋해" 같은 지속 지시는 요청으로 세지 않으므로 **"요청 없음"은 상한에 가깝다.**

### 세션별 차이

세션마다 요청 없는 비율이 크게 다르다. 예를 들어 어떤 세션은 컨텍스트 15만~17만에서도 4건 모두 요청 없이 커밋했고, 어떤 세션은 커밋 3건 모두 요청받은 것이었다. 즉 컨텍스트 크기 말고 세션마다의 요인(작업 방식, 지시 문구)이 크게 작용한다.

## 해석

- 요청 없는 커밋은 흔하다 (자료 1에서 65%). 규칙 위반 자체(H1)는 이 기록으로 뒷받침된다.
- 컨텍스트가 클수록 비율이 조금 높다 (10~20만 53%, 20~40만 69%, 40만 이상 70%). 같은 세션 안에서도 6개 중 5개가 같은 방향이다. 하지만 효과는 크지 않고, **10~20만에서도 절반 이상이 위반**이라 "아주 긴 컨텍스트가 필요하다"는 설명과는 맞지 않는다.

## 한계

- 통제 없는 관찰이다. 컨텍스트가 커지는 것과 세션이 오래 진행되는 것(턴 수)은 함께 늘어서 분리할 수 없다.
- 후반부에는 사용자가 커밋을 명시적으로 요청하는 빈도 자체가 줄었을 수 있다.
- 요청 판정은 키워드 기준이라 오분류가 있다 (자동 판정이 요청으로 인정하지 않은 지속 지시·짧은 승인).
- 세션 10개, 모델 3종이 섞여 있고 세션별 편차가 크다.
- 개입(규칙 요약 노트, 슬라이싱)의 효과는 이 자료로 알 수 없다.
